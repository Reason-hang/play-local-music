## 1．目标、范围与事实来源

目标：对看到并点击的媒体准确执行收藏和播放；首页控制入口不依赖滚动；全屏视频可在非控件画面及启用的播放／暂停按钮双击暂停／继续；置顶与普通区域有主题色分隔。补充范围为移除首页重复“文件系统”页和纯数字版本名。两个 App 共用实现，分别验收。

本轮用户已补：两个 App 均为 V1.7.7，出现问题时有置顶、记得点过收藏，第一项仍可能被操作成第二项。未证明无置顶、刚启动且未收藏也出现。已证实播放根因见 [实现后审计 REL-005](../05-测试与验收/07-1.7.9实现后代码审计与修复报告.md#rel-005-已复现的播放端根因)；实施前证据和反例见 [专项调查与对抗审查](../05-测试与验收/06-双App交互专项调查与对抗审查-2026-10-10.md)。

事实源：1.7.7 提交 `67f3ab96ebce7cde6b49b1499c0425927efb0106`；旧版相关五组件与已提交 HEAD 无差异。用户报告版本不能证明实装包字节与本地 APK 相同。当前补丁、专项模型测试和原机故障分开记录。

## 2．需求与建议默认规则

| 需求 | 可验收结果 | 规则／边界 |
| --- | --- | --- |
| 收藏／播放目标准确 | 显示、触摸、绑定、请求、实际执行身份一致 | 原因可能不止一个；更多菜单和高亮一并回归；无效／已移除行不误操作其他项 |
| 全屏双击 | 一次双击切换一次暂停／继续 | 全 PlayerView 非控件画面及启用的播放／暂停按钮；禁用控件、其他按钮和 TimeBar 排除；控件 DOWN／失焦取消旧候选；保留按钮单击并复用会话 |
| 首页固定播放条 | 不滚动即可看到，滚动不隐藏，末项可读 | 固定于底部安全区域；展开／返回保持原交互；不自动播放 |
| 置顶分隔 | 两类同时存在时边界明确 | 主题色、非歌曲元素、不改变队列和索引；空／全置顶无多余边界 |

当前规则：无媒体仍显示“请选择歌曲／课程”空态，清除旧内容并禁用无效操作；全屏双击不再限定为中央窄区，保留启用的播放／暂停按钮的双击和原单击；常驻范围为首页及其列表场景。首页保留歌曲、艺术家、文件夹、播放列表四页；FileSystem enum、旧偏好字符串及底层目录读取保留，移除入口和排序选项，旧仅含 FileSystem 的配置回退歌曲。

数据边界：隐藏、分类、置顶、断点及应用偏好私有；收藏沿用公共 Favorite 文件，**不能承诺收藏关系已按 Flavor 隔离**。本轮不自动改文件名、不迁移收藏、不改媒体身份格式、不删除源文件、不恢复撤回视觉方案。

## 3．方案取舍

推荐：沿用现有列表、MediaSession 和 BottomSheet，按已证明的首个分歧层进行局部修复，补全状态和验收；成本与影响面最小。

备选：若运行证据证明现有布局／触摸结构无法可靠修复，才评估调整行布局或播放器容器。暂不选择独立播放条状态机、第二个播放器、整体界面重构或私有收藏迁移；它们增加同步、升级和回退成本，没有当前证据支持。

## 4．执行步骤与阶段门槛

| 阶段 | 工作与产出 | 进入下一阶段的条件 |
| --- | --- | --- |
| S0 基线 | 原机版本、最小步骤、关联身份；必要时只读取 APK／匿名诊断 | 清楚调查哪个二进制与场景，不把候选补丁当现场 |

| S2 最小修复 | 对已证明根因修复；无效位置、媒体身份、重复项位置、高亮；收藏请求关联、串行写、去重和结果回流 | 针对失败步骤的前后对照通过；跨 App 风险单列 |
| S3 常驻播放条 | 页面意图、会话连接、Behavior／Insets 就绪时重算最新状态；空态、取消迟到任务、底部留白 | 冷启动不滚动、空态、已有队列、后台返回及末项通过 |
| S4 双击与分隔 | 标准手势识别、既有播放语义、全画面及启用播放／暂停按钮命中，排除其他控件；完成主题分隔 | 缓冲／结束／断连边界、控制栏与列表索引正常 |
| S5 验证 | 先修测试夹具；正常双 Flavor 全量测试、相称静态检查、串行构建、产物检查、Redmi 定向操作 | 最终源码验证通过，设备不足明确保留待验，不越级 |

估时：在根因已复现且不需要收藏迁移的前提下，本地实施与自动化约 3～5 小时；Redmi 定向验收约 30～60 分钟。设备／系统授权与公共文件写入取证单列，不承诺未知等待时间。

## 8．风险、纠错与提前注意

| 主要风险 | 预防／纠错 |
| --- | --- |
| 首个分歧在触摸或服务层，身份兜底无效 | S1 不以假设跳过；按实际故障层调整范围 |
| 单进程串行化被误认为跨 App 原子性 | 公共收藏明确保留边界，双 App／旧版交互另测 |
| 强制显示旧播放器导致旧标题、失效按钮或遮挡 | 先补空态和最新状态，再显示；同步 Insets |
| 双击使用 isPlaying 或独立本地状态 | 复用 playOrPause／会话，覆盖缓冲、结束和命令延迟 |
| 范围扩大成架构替换、收藏迁移或身份格式变化 | 无证据不扩大；数据迁移须另行确认，留兼容／回退设计 |

回退：按内容提交追溯修改；交付后按功能单独回退并重建同包名、兼容签名、更高 versionCode 的包；真实用户数据保留未实测前不承诺降级安全。不要卸载主力 App 或覆盖公共收藏做破坏性试验。

## 9．当前进展与证据边界

播放端已通过实际 ExoPlayer 复现：EndedWorkaroundPlayer 使用 `[startIndex,startIndex)` 空区间，实际执行插入，导致当前项后移或队列重复。修复为 `[startIndex,startIndex+1)` 后，旧实现四项全部失败的前后对照已闭环，最终两变体各六项无缝队列回归通过。原机收藏单次触摸及完整组合触发时序仍待验。

调查阶段的六项专项和失败夹具记录保留为历史。1.7.9 实施阶段已完成共享交互、收藏写入、常驻空态、双击和分隔，当时双变体各 108 项及 Release Lint 0 错误。截图为 Robolectric 原生绘制。当前原机已授权，完成本地诊断候选覆盖及双击确认；真实收藏授权、原机错位完整触发时序、硬件视频矩阵和升级数据逐字段保留仍待验。

2026-10-10 双击现场：1.7.9／42 诊断记录了 20 个 DOWN／UP，触点 x=1726～1984，而旧 W=2400 时允许区仅 x=800～1600；间隔 96～111 ms＜300 ms、单指移动＜1 px，播放器 connected、PLAY_PAUSE=true、count=212、READY，却无 double 回调。首个分歧为命中区过窄。旧真实坐标回归 1 项失败，新实现 16 项 Interaction 专项通过；本地诊断候选两状态实机获用户确认。正式源码已移除详细逐触点诊断，仅保留简短本地 double 事件。

本质：不是让索引“看起来对”，而是操作对象可追溯、异步结果不串项、控制入口与真实会话状态一致。实施方案服从证据，验收结论服从实际执行范围。
