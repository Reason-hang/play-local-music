# MP4 视频方案评估

状态：1.7.4 已采用方案；更新时间：2026-08-22。

视觉实现说明：HTML Demo 只作为视觉契约；播放页和全屏入口已映射到原生 Compose，实际视频输出仍复用既有 `VideoPlayerActivity`、Media3 `PlayerView` 与前台媒体服务。

| 方案 | 结论 |
| --- | --- |
| 新建视频播放器项目 | 不采用：播放状态、锁屏和队列会分叉，违反最小改动原则。 |
| 只播放 MP4 音轨 | 已完成历史阶段，但不能满足看画面。 |
| 复用 Media3 播放器并增加全屏渲染页 | 已采用：同一 MediaSession、同一队列、同一前台服务，MP4 + AAC 首要验收。 |

实现：`Reader` 查询 `MediaStore.Video`，用 `MediaExtractor` 检查 `audio/mp4a-latm`，命中后加入媒体库。播放页按 `MediaType` 或 MIME `video/*` 显示嵌入式画面；点击画面进入横屏全屏 `PlayerView`。两个页面均使用 `TextureView`，切换时先释放旧输出，再绑定新输出；全屏只控制渲染面，后台/锁屏继续由服务处理。

实样本证据：已用 `ffprobe` 检查两份用户 MP4，均为 HEVC Main、1280×720、`yuv420p` 视频加 AAC-LC 音轨。扫描与播放器可识别视频轨，但 HEVC 硬解、横竖画面与 HyperOS 后台策略仍须红米 K80 Pro 真机验证。

断点续播不创建视频播放器或第二队列：服务层以视频指纹保存位置，自定义媒体入口使用展开后的真实起播索引，队列切换在替换时间线前计算目标视频位置；只有手动回到视频时恢复，自动连续播放保持 0:00 起播，避免课程连续播放被历史进度打断。
