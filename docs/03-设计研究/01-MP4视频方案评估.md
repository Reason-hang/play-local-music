# MP4 视频方案评估

状态：既有方案在 1.7.10 继续沿用；全屏双击覆盖非控件画面及启用的播放／暂停按钮，复用原会话及 PlayerView。更新时间：2026-10-10。

1.7.10 最终双变体各 120 项测试通过、0 失败；Release Lint 两包均 0 Error／Fatal，警告 local 140／course 147。内容提交 A：`7c508ed4c28de663411a4e8fe586bb3415aea984`。正式双包已构建验包；用户已拔下手机并要求先交付APK，最终课程版／首页真机及完整数据对照待验。

| 方案 | 结论 |
| --- | --- |
| 新建视频播放器项目 | 不采用：播放状态、锁屏和队列会分叉，违反最小改动原则。 |
| 只播放 MP4 音轨 | 已完成历史阶段，但不能满足看画面。 |
| 复用 Media3 播放器并增加全屏渲染页 | 已采用：同一 MediaSession、同一队列、同一前台服务，MP4 + AAC 首要验收。 |

实现：`Reader` 查询 `MediaStore.Video`，用 `MediaExtractor` 检查 `audio/mp4a-latm`，命中后加入媒体库。播放页按 `MediaType` 或 MIME `video/*` 显示嵌入式画面；点击画面进入横屏全屏 `PlayerView`。两个页面均使用 `TextureView`，切换时先释放旧输出，再绑定新输出；全屏只控制渲染面，后台/锁屏继续由服务处理。

实样本证据：已用 `ffprobe` 检查两份用户 MP4，均为 HEVC Main、1280×720、`yuv420p` 视频加 AAC-LC 音轨。扫描与播放器可识别视频轨。本地诊断候选已在 Redmi 24122RKC7C／API 36 播放现场完成控制栏显示／隐藏双击暂停／继续确认；这不覆盖 HEVC 硬解矩阵、完整横竖切换与 HyperOS 后台策略，仍须正式双包验证。

断点续播不创建视频播放器或第二队列：服务层以视频指纹保存位置，自定义媒体入口使用展开后的真实起播索引，队列切换在替换时间线前计算目标视频位置；只有手动回到视频时恢复，自动连续播放保持 0:00 起播，避免课程连续播放被历史进度打断。
