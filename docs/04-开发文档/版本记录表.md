填写规则：

1. 一个版本可以对应多个提交，不能用单个 SHA 代替全部版本来源。
2. `versionName` 是用户版本号；`versionCode` 是 Android 安装覆盖和发布平台识别依据。
3. 生命周期、质量门禁、发布状态必须分开填写。
4. 新增、修改、修复、删除四项必须全部出现；无对应事项写“无”。
5. 升级、覆盖安装、降级、迁移和回滚结论必须区分“已验证”和“设计上可行”。

#### 4.3 版本目标与用户价值

- 版本目标：让用户可以长期收藏歌曲，并把当前经常查找的歌曲手动置顶，降低在长列表中反复查找的成本。
- 用户价值：爱心表达“我喜欢它”，收藏筛选进入长期收藏列表；置顶表达“我现在经常找它”，在当前列表优先展示。
- 本次最重要变化：收藏和置顶保持独立，取消置顶只恢复原排序，不删除收藏关系。

#### 4.4 功能变化

- 新增：歌曲列表行和网格卡片的爱心按钮；“收藏”筛选；歌曲更多菜单的“置顶 / 取消置顶”。
- 修改：收藏沿用既有 `Favorite` 播放列表作为唯一关系来源；置顶由 `LocalLibraryManager` 在应用私有状态中独立持久化；主列表、分类列表和播放列表均按“置顶优先、未置顶保持原排序”展示。
- 修复：常听歌曲必须反复滑动查找、收藏关系没有列表快捷入口的使用问题。
- 删除：无。
- 受影响功能：歌曲列表、分类列表、播放列表、播放器收藏状态和本地整理状态。
- 数据与文件影响：收藏操作复用既有收藏播放列表；置顶 JSON 使用 MediaStore ID 和路径 SHA-256 双身份键，不改写用户媒体文件；旧状态缺少 `pinned` 字段时按空置顶集合读取。

## 6. 版本链路补充

- 版本号与 `versionCode` 不是单调提交链：`v1.7.2` 为 37，`v1.7.3` 为 38，`v1.7.4` 为 39；回滚后恢复 `v1.7.2` 的 37，再发布 `v1.7.5` 的 38、`v1.7.6` 的 39，当前 `v1.7.7` 为 40。
- `v1.7.3` 和 `v1.7.4` 虽有代码、构建和静态验证证据，但已撤回；不能视为当前用户应安装的版本。
- `v1.7.5` 的实际升级基线是回滚后的 `v1.7.2`，不是已撤回的 `v1.7.4`。
- “最近 5 个版本”在本表中按最近 5 个 `versionName` 统计；如果后续同一版本发生多次构建、撤回或正式发布，应另加“版本事件”记录，不能只靠版本号判断时间顺序。
- 当前台账把自动化、APK 静态校验、真实设备验收和正式发布分开记录；Robolectric、构建成功或 ADB 无设备都不等于 Redmi K80 Pro 真机通过。
