## 一、任务上下文

目标是在不重构上游架构的前提下交付简体中文、本地优先、重点支持 MP3 的 Android 16 MVP。决策优先级为安全与数据正确、核心播放可用、稳定性、可维护性、效率。高风险不可逆操作不执行；所有无法实测的结论标为待验证。

## 二、决策记录

### D-001 源码选型

- 风险等级：中。
- 候选方案：新建播放器、采用用户指定的上游 FoedusProgramme/Gramophone、换用其他播放器。
- 依据：用户明确指定 FoedusProgramme/Gramophone；上游已有 MediaStore、Media3、队列、后台和媒体控制能力。
- 结论：采用 `beta` 分支，基线提交 `eacd986`；不重构。
- 执行动作：初始化源码和两个子模块。
- 回滚条件：上游无法编译或核心功能缺失时回到基线，不扩大功能范围。

### D-002 网络处理

- 风险等级：中。
- 方案：彻底清理、仅关闭入口、保持原状。
- 依据：用户确认方案 B；需删除权限并保证主流程离线，且不全面清理底层依赖。
- 结论：删除网络/图片权限，移除外链更新入口，保留底层歌词/封面/均衡器代码。
- 验证：通过合并清单检查和源码入口扫描验证，运行时飞行模式待设备验证。

### D-003 无用入口处理

- 风险等级：低至中，可回滚。
- 结论：移除均衡器菜单与分支；隐藏歌词按钮；删除歌词、封面设置节点；保留底层实现。
- 依据：用户要求先隐藏/关闭调用路径，避免架构重构。

### D-004 Android 16 SDK 口径

- 风险等级：中。
- 依据：Android 16 为 API 36，本机已安装 Platform 36，本机 SDK 仓库没有可用 Platform 37。
- 结论：将 `compileSdk`/`targetSdk` 从 37 调整到 36，使构建可复现且与目标系统对应。
- 遗留风险：上游未来 API 37 特性未覆盖；当前源码未发现必须使用 API 37 的代码。

### D-005 签名与交付

- 风险等级：中。
- 结论：先以 `package.properties` 固定 `releaseType=SelfBuilt`，构建后检查是否产生签名 APK；若未签名，不冒充可安装交付，会补充可回滚的本地签名方案。

### D-006 依赖与 Android 36.1

- 风险等级：中。
- 现象：`mediastorecompat` alpha31/32 的 AAR 元数据要求 API 36.1；源码还调用了 alpha32 才提供的封面接口。
- 结论：启用 `compileSdkMinor = 1`，由 SDK 管理器安装 Platform 36.1；封面管线改用系统 `ContentResolver`，不升级到 API 37，不改变播放器架构。
- 证据：Release 构建 `:app:assembleNonMinifiedRelease` 退出码 0。

### D-007 上游构建插件兼容

- 风险等级：中。
- 现象：Gradle 9.4.1 下 `pt.jcosta.resourceplaceholders` 任务读取时序失败。
- 结论：移除该仅用于 XML 占位符的插件，短快捷方式改为固定包名；不影响运行时功能。
- 证据：后续 Release 打包通过。

### D-008 离线权限闭环

- 风险等级：中。
- 结论：主 manifest 使用 `tools:node="remove"` 清除依赖传入的 `ACCESS_NETWORK_STATE`，并核验 APK 不含 `INTERNET`、网络状态或图片权限；保留底层库但不开放网络入口。
- 证据：`aapt2 dump badging`/`dump permissions` 未发现上述权限。

### D-009 测试失败归因

- 风险等级：低至中。
- 结论：为 Robolectric 测试进程增加 JDK 21 模块导出参数；修复环境初始化后 37/38 测试通过，剩余 1 个上游歌词期望断言失败，不改业务代码掩盖。
- 证据：`app/build/test-results/testDebugUnitTest/TEST-org.akanework.gramophone.LrcUtilsTest.xml`。

### D-010 产品名称统一

- 风险等级：低至中。
- 触发：用户要求将工具、APK 名称和全部项目文档统一改为“本地听歌”。
- 结论：应用内 `app_name`、播放列表导出显示名、APK归档名、README和本地交付文档统一使用“本地听歌”。
- 兼容边界：保留 `org.akanework.gramophone` 包名、`Gramophone*` 类名、主题名和源码目录 `work/Gramophone`，避免破坏已安装版本的更新兼容和上游技术引用。
- 验证：重新构建后检查 APK 应用标签、文件名、文档旧名称扫描和哈希记录。

### D-011 MP4 + AAC 音频兼容

- 风险等级：中。
- 变化点：用户需要保留 MP4 的 AAC 音轨播放与锁屏音频，不需要视频画面；Android 13+ 的音频、视频媒体读取权限分离。
- 候选方案：
  - A：新建视频播放器或给现有播放器增加视频渲染器。能力最广，但会扩张 UI、交互和测试面，违背本次范围。
  - B：只通过文件选择器临时打开 MP4。改动小，但扫描、歌单和队列无法与 MP3 一致。
  - C：在现有 MediaStore/Media3 链路中读取 `MediaStore.Video`，仅接纳有 AAC 音轨的 MP4。能复用队列和后台服务，改动集中在扫描、权限和 URI 传递。
- 结论：选择 C。新增 `READ_MEDIA_VIDEO` 最小读取权限；使用 `MediaExtractor` 对每个候选 MP4 检查 `audio/mp4a-latm`，命中后创建音频用途 `MediaItem`，但不创建视频渲染器。
- 安全与兼容：删除、搜索建议、外部选曲均传递原始 MediaStore URI，避免把视频 ID 错拼成音频 URI；网络方案 B 和权限删除规则保持不变。
- 验证：新增 `Mp4AacSupportTest` 覆盖 AAC 接受、缺失 MIME 的 `.mp4` 回退、非 AAC 拒绝、非 MP4 拒绝；本地用户样本经 `ffprobe` 识别为 AAC-LC。无 ADB/模拟器时，锁屏结论仅能基于既有前台媒体服务静态链路，保留真机验收。
- 回滚条件：扫描性能明显下降、厂商 MediaStore 返回异常或实机 MP4 + AAC 无法开始播放时，关闭视频集合扫描即可恢复 MP3 基线，不影响既有播放服务。

### D-012 构建与静态检查处置

- 风险等级：中。
- 事实：`compileDebugKotlin` 与 `assembleNonMinifiedRelease` 通过；新增 MP4 + AAC 测试 4/4 通过。全量单测仍保留 1 个既有歌词期望失败，`lintDebug` 报告 9 个既有错误和 96 个警告。
- 候选方案：修改无关上游歌词/Lint 问题以追求全绿，或保留问题并透明交付。
- 结论：选择透明交付。当前任务的验收核心是 MP4 + AAC 与媒体服务兼容，不扩大为上游全面治理；所有失败来源、APK 签名和对齐结果都写入验证记录。
- 验证：APK 版本 `1.1.2.19c8a81`，SHA-256 `34ad2f24e98b88deb5d02d01a525ff3e4d0916b96f4b2db6d4016ec42fc941db`，v1/v2 签名与 zipalign 均通过。
