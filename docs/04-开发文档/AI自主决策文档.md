## 决策原则

以安全、可用、可验证和最小影响面为优先级。结论只建立在源码、构建输出、日志或明确的真机证据上；没有设备证据时标记为待验证，不用推断替代结果。

## 决策记录

### D-001 源码与产品边界

- 背景：用户指定 `FoedusProgramme/Gramophone` 为基础，要求不重构。
- 方案：新建播放器、替换播放器、基于既有 Media3 服务扩展。
- 结论：扩展既有架构；保留技术包名与类名，产品名统一为“本地听歌”。
- 验证与回滚：所有变更集中在扫描、渲染、设置和诊断层；可按单个变更回退。

### D-002 离线方案 B

- 背景：核心本地播放必须不依赖网络，但不做全量依赖重构。
- 结论：不声明 `INTERNET`，移除网络状态权限和可见在线入口；保留底层非可达代码。
- 验证：合并清单与 APK 权限检查；飞行模式真机验证待补。

### D-003 MP4+A​​AC 与完整视频

- 背景：已有 MP4 音频播放，用户升级为需要画面且熄屏继续有声。
- 方案：独立视频项目、仅音频、现有 ExoPlayer 启用视频渲染。
- 结论：启用现有 `GramophoneRenderFactory` 的默认视频渲染器，在完整播放器绑定 `PlayerView`；MP4 扫描维持 AAC 轨筛选。
- 依据：单一 ExoPlayer/MediaSession 可保持队列、锁屏和蓝牙控制一致，不引入第二个播放状态机。
- 回滚：恢复空视频渲染器与封面显示即可回到音频版。

### D-004 行为设置必现崩溃

- 背景：Android 16 日志指向 `BehaviorSettingsFragment.onResume` 的空指针。
- 根因：`settings_behavior.xml` 已删除 `album_covers`，Kotlin 仍以 `findPreference(...)!!` 强引用；API 33+ 必进该分支。
- 方案：恢复节点、判空、删除孤儿逻辑。
- 结论：删除同源的 `onResume` 和点击分支。恢复权限相关 UI 会违背当前产品范围；判空会留下确定的死逻辑。
- 验证：`compileDebugKotlin` 通过；目标机点击路径待回归。

### D-005 崩溃页锁死与诊断体系

- 背景：旧 `BugHandlerActivity` 强制邮件弹窗没有取消按钮，并收集整机 `logcat`。
- 方案：保留旧弹窗、接入远程平台、本地有界诊断。
- 结论：删除旧 Activity 与强制邮件链路；新增私有目录诊断、用户主动导出、清除功能。
- 隐私：不自动外发，不记录媒体路径、标题、URI、剪贴板或输入内容。
- 回滚：删除诊断入口不影响播放器；保留平台默认崩溃处理。

### D-006 发布签名

- 背景：没有用户提供的正式 keystore。
- 结论：交付 SelfBuilt debug 签名 APK，并在文档和产物说明中如实标注；不生成或替代用户的生产私钥。
- 后续：收到正式密钥后单独验证升级路径。

### D-007 构建交付与真实状态

- 背景：用户要求一次性交付可安装 APK，同时禁止把未验证结果当作完成。
- 事实：`assembleDebug` 成功，产物通过 `aapt2` 包名、版本、SDK 与权限检查；`assembleNonMinifiedRelease` 连续失败于上游 Media3 的 ALAC/MIDI Release Java 编译类路径，无法解析 ExoPlayer 音频类。
- 结论：交付 Debug/SelfBuilt APK，并明确其安装边界和 SHA-256；Release 故障单列为 P0 构建债务，不通过伪造密钥、降级证据或把 Debug 改名的方式掩盖。
- 后续：先复现并最小化上游 Release 依赖图，再决定修复 Gradle 依赖、排除无关解码器或升级上游版本的最小方案。

> 2026-08-08 复核：在恢复本机 JDK 21 与 Android SDK 36 后，`:app:assembleNonMinifiedRelease` 通过。此前“Release 依赖阻断”不能再作为当前结论；未闭环项变为正式私钥、签名与升级路径，而不是编译本身。

### D-008 静态检查遗留阻断

- 背景：首次 `lintDebug` 报 9 个错误、127 个警告，无法满足“静态检查完成”的交付标准。
- 方案：仅记录、建立 baseline、修复 9 个错误。
- 结论：修复 3 个不再受支持的 `SessionResult` 错误码、1 个 Media3 实验 API 标记，以及 5 个把百分号当格式符的翻译资源；不建立 baseline 遮蔽现有问题。
- 验证：当前 `lintDebug` 通过，0 个错误、124 个警告。剩余警告列入后续治理，不阻断本次 APK 安装验证。

### D-009 上一首与预设倍速

- 背景：`seekToPrevious()` 的默认 3 秒阈值会在不同进度下重播当前项或切到上一项，锁屏与蓝牙复用了同一语义；速度滑条不符合固定档位的使用诉求。
- 方案：仅改页面按钮、重写媒体会话命令、调整 ExoPlayer 全局阈值。
- 结论：在 ExoPlayer 构建处将上一首阈值设为最大值，确保所有入口统一；速度改为六档单选预设，保留音高滑条与锁定开关，但无历史配置时默认不锁定，重置也不锁定。
- 边界：队列第一项没有上一项，仍回到本项开头；旧自定义速度不再提供可选项，用户需手动选择预设档位。
- 验证：`PlaybackSpeedPresetTest`、相关 MP4/诊断/设置回归测试与 `lintDebug` 通过；1.3.2 Debug APK 构建并完成清单检查。锁屏、蓝牙和第一项边界仍待红米 K80 Pro 真机回归。

### D-010 SelfBuilt 安装包隔离与外部审计复核

- 背景：用户安装 1.3.2 后，Android 16 重复显示 StrictMode 违规弹窗，启动器出现“本地听歌”“Reflections”“Leaks”三个图标，且图标变为圣诞样式。两份外部审计报告同时指出 Debug 构建进入日常交付的边界问题。
- 根因：`GramophoneApplication` 在 `BuildConfig.DEBUG` 下配置 `StrictMode.penaltyDialog()`；`src/debug/AndroidManifest.xml` 覆写 `ic_launcher_xmas` 并注册 `Reflections` 为启动 Activity；`debugImplementation(leakcanary-android)` 注入 LeakCanary 启动入口；debug 源集还合并了 userdebug 代码。
- 方案：保留 `.debug` applicationId 以覆盖已安装的 1.3.2，或切换基础包名并要求用户先卸载。结论：选择前者，避免本次修复再新增一个图标；删除 StrictMode、调试 Manifest、LeakCanary 与 debug/userdebug 源集合并；将用户交付变体设为 `debuggable=false`，保留主图标与唯一 `MainActivity` 启动入口。
- 审计处理：对诊断生命周期、脱敏与存储边界、MP4 大库性能、设置 key 强引用、Release 签名、原生 C++ 覆盖范围逐项记录在《审计复核与后续任务》；静态推断未写成真机结论。
- 验证与回滚：构建后检查 `BuildConfig.DEBUG=false`、合并清单仅一个 `MAIN` + `LAUNCHER`、无 LeakCanary/Reflections/StrictMode 调用；同包名安装覆盖 1.3.2。若发生升级问题，可仅回退本决策涉及的调试源集与构建配置。

### D-011 交付产物验证与风险边界

- 背景：用户需要能覆盖 1.3.2 的可安装包，但目标机本轮未通过 ADB 连接，不能以构建通过替代真机结论。
- 结论：交付 `1.3.3.7e1e6b9`、`versionCode 27` 的 `.debug` 同包名 APK。已完成构建、8 项定向单测、Lint（0 Error/124 Warning）、`aapt2` 权限和唯一启动入口检查、v1/v2 签名与 zipalign 检查。
- 未闭环：红米 K80 Pro 的覆盖更新、图标、StrictMode 弹窗、视频画面、锁屏、蓝牙与飞行模式；既有歌词单测 1 项失败；正式 release keystore 和商店级签名。
- 原则：把未连真机的运行时风险明确交给下一轮验收，不以静态证据掩盖。

### D-012 本地媒体库整理与全屏视频

- 上下文：用户需要长标题易读、MP3/MP4 快捷筛选、自定义分类、非破坏性隐藏、诊断一键复制和 MP4 全屏；此前“不新增分类、永久忽略”的范围已被当前明确需求替代。
- 风险等级：中。媒体整理状态若只依赖 MediaStore 临时 ID，重扫后可能失效；全屏若重建播放器，会造成队列、进度和锁屏状态分叉。
- 候选方案：一是只改列表样式并把分类交给系统播放列表，改动小但无法实现可恢复隐藏和多分类；二是新建独立媒体库或视频项目，隔离强但违反不重构边界；三是在应用私有状态中保存隐藏/分类关系，复用现有 MediaStore、MediaSession 和 ExoPlayer。
- 结论：采用方案三。隐藏键同时保存 `MediaStore` ID 与文件路径哈希；分类是可多归属的本地标签；首页只增加“全部、MP3、MP4”和动态分类筛选。全屏页单独连接既有媒体服务，不创建新的播放器。
- 验证与回滚：对隐藏重扫、恢复、分类计数、格式筛选、全屏进退、锁屏连续播放做定向回归；如全屏连接异常，隐藏全屏入口可回退至现有嵌入式 `PlayerView`，不影响音频播放。

### D-013 1.4.0 交付实现与证据边界

- 背景：用户要求在同一交付中完成媒体库整理、首页可读性、全屏 MP4 和诊断一键复制，并要求 APK 文件名不出现 `debug`。
- 方案：变更应用 ID，或保留 `org.akanework.gramophone.debug` 并只调整文件名。
- 结论：保留应用 ID 与 `versionCode` 单调升级，以覆盖已安装的 1.3.2/1.3.3；导出的用户安装包命名为 `本地听歌-1.4.0.apk`。文件名不表示签名类型，交付说明必须仍标注 SelfBuilt 签名。
- 实施：隐藏状态使用 `MediaStore` ID 与路径哈希双键，分类使用应用私有 JSON；扫描层过滤隐藏项，避免重扫重新出现；全屏页只绑定既有 `MediaBrowser`；诊断摘要仅在用户点击时写入剪贴板。
- 验证：先执行 Kotlin 编译，再执行定向单测、完整构建、Lint、APK 结构/权限/签名检查。没有连接红米真机时不宣称真机通过。
- 回滚：删除私有状态会恢复被隐藏的媒体；撤销全屏入口回到嵌入式视频；不触碰手机原始文件。

### D-015 隐藏媒体的恢复原子性

- 背景：隐藏状态同时包含 ID 键与路径哈希键，以抵抗 MediaStore 重建；若让用户按单键恢复，会留下另一把键继续过滤该媒体。
- 方案：只存单键、建立复杂的键对映射、或提供“恢复全部已移除内容”。
- 结论：当前 MVP 采用恢复全部。它保持双键可靠性和原子性，避免出现“已恢复但仍不可见”的失败体验；不删除或修改任何源文件。
- 后续：若需要逐条恢复，先把隐藏状态升级为含显示名称（经脱敏策略审查）的成对记录，再补单测。

### D-017 视频输出交接与完整播放器修复

- 背景：真机截图显示 MP4 音频可播，但竖屏封面占位、横屏可能停在旧帧、锁屏后通知栏播放会立即回到暂停。根因不能归为“MP4 不支持”：`Reader` 已确认 AAC 轨且声音持续，问题发生在画面识别与输出生命周期。
- 根因：内嵌页仅以 `MediaMetadata.mediaType` 判断是否显示视频；持久化队列恢复时该字段可能缺失。并且内嵌与全屏 `PlayerView` 会在切换、横屏重建和锁屏时竞争同一服务播放器的视频输出。
- 结论：视频识别增加 MIME `video/*` 兜底；两处播放器使用 `TextureView`；启动全屏前和页面停止时清空旧 `PlayerView.player`，回到主页后再绑定；横屏由 Manifest 在 Activity 创建前确定，避免 `onCreate` 后强制旋转导致重建；全屏左上角提供返回按钮并设置常亮。
- 倍速：覆盖 Media3 原生 `exo_controls_playback_speeds`，统一为 0.75、1、1.3、1.5、1.7、2 倍，移除 0.25 倍。
- 验证与边界：新增 `VideoPlayerActivityTest` 验证全屏页面、返回按钮、横屏声明和原生倍速资源；MP4+A​​AC 扫描测试保留。真实 Android 16/HyperOS 锁屏与硬件视频解码仍必须用用户样本真机复验；若仍失败，下一步取诊断包与 `adb logcat` 的 `MediaCodec`/`ExoPlayer` 错误，而不是盲改音频服务。

- 结论：交付 `本地听歌-1.4.1.apk`（versionCode 29、SelfBuilt 签名），并完成 APK 权限、签名、对齐检查。单测结果为 47 通过、1 个既有歌词解析失败；Lint 为 1 Error / 128 Warning，唯一 Error 是既有歌曲列表 XML 约束缺失，本轮新增的 Media3 私有倍速资源覆盖已用 `tools:override` 消除警告。

### D-019 当前不确定性与遗漏复核

- 最高不确定性：当前 `Reader.inspectMp4Tracks()` 只确认 MP4 容器内有 `audio/mp4a-latm`（AAC）和 `video/*` 轨，未验证视频编码、Profile、Level、色彩格式与设备 `MediaCodec` 能力。因此“声音正常、画面无/静止”可能来自输出面生命周期，也可能来自 H.264/HEVC 等视频轨的硬解兼容性；未连接红米前不能宣称已彻底定位为单一根因。
- 锁屏根因边界：前台 `MediaLibraryService` 与媒体播放前台服务权限均已存在，但“锁屏播放后立即回暂停”仍缺 `MediaSession`、Audio Focus、前台服务状态和 `MediaCodec` 日志。当前修复消除了双视频输出面竞争，不能替代实机事件链证明。
- 诊断能力遗漏：当前 `DiagnosticStore.recordEvent()` 仅覆盖应用启动和 `onPlayerError()`；它不能说明锁屏时是否失去 Audio Focus、服务是否存活、播放器状态为何从播放变暂停、视频渲染器为何不出帧。下个故障修复版本应在不记录媒体路径/标题的前提下，补充这些状态转换的脱敏事件。
- 发布追溯遗漏：用户安装包文件名为 `1.4.1`，但 Gradle 非 Release 变体自动在应用版本后追加构建时 HEAD 短哈希；若先构建、后提交，APK 的短哈希会落后于最终源码提交。后续交付必须固定“提交后构建”或取消用户可见的哈希后缀，并在 APK、SHA、提交号三者间做一致性校验。
- Android 16 边界：`sensorLandscape` 满足手机横屏体验，但 Lint 已提示固定方向在部分 Android 16 设备形态可能被系统忽略。红米手机可作为首要验收目标；平板、折叠屏不在 MVP 承诺范围。
- 后续动作：连接红米和实际 MP4 样本后，执行竖屏、横屏、进退全屏、锁屏 30 分钟、锁屏通知恢复、蓝牙、飞行模式六轮矩阵；失败时导出诊断包并采集限定标签的 `adb logcat`，再按音频焦点、服务存活、视频解码、输出面四层定位。

### D-020 1.4.2 播放诊断闭环与版本可追溯

- 背景：用户要求针对“MP4 竖屏无画面、全屏静帧、锁屏回暂停”等未确定问题继续修复并打包。现有代码只能在 `onPlayerError()` 看到错误，复制摘要没有播放状态时间线，且脱敏仅覆盖文件路径。
- 实样本核验：通过 `ffprobe` 检查两份用户 MP4，均为 HEVC Main、1280×720、`yuv420p` 视频和 AAC-LC 音轨；因此不能把问题归为“不是视频文件”。但没有红米设备的 `MediaCodec` 运行记录，仍不能断言是硬解还是输出面生命周期。

### D-021 媒体库移除语义与首页可读性闭环

- 背景：用户实际点击“删除”后系统请求删除手机源文件，说明虽然“媒体库整理”已有隐藏能力，但单曲、专辑、音乐人菜单仍保留破坏性路径，产品语义与入口不一致；同时长课程标题两行不足以辨识，随机图标难以让非技术用户理解。
- 根因：三个媒体适配器共用了包含 `delete` 的菜单，并直接调用 `ItemManipulator.deleteSongs()`；应用私有隐藏入口被放在二级整理页，不能阻止用户从更近的单曲菜单误触系统删除。旧隐藏状态只保存键，无法为用户逐项恢复提供名称。
- 候选方案：A. 仅重命名“删除”，但仍调用系统删除，语义欺骗且不可接受；B. 新增隐藏功能但保留旧删除入口，用户仍会误触；C. 为单曲建立独立菜单并改为私有隐藏，专辑/音乐人撤掉媒体删除入口，保留播放列表本身的删除。采用 C：媒体源文件从所有可达媒体入口均不可删除，播放列表删除不改变手机媒体，不属于同一风险。

- 界面取舍：整理页采用居中的四个同宽圆角动作按钮和辅助说明；选择与恢复列表使用复选框、两行截断和浅色虚线分隔。首页列表标题升级为最多三行、16sp；随机播放改为骰子图标，并在系统锁屏控件仍使用系统提供的标准随机图标，不尝试越权替换。
- 版本与验证：升级为 versionCode 31、versionName `1.5.0`。新增 `LocalLibraryManagerTest` 验证“恢复所选项不影响其他隐藏媒体”，新增 `LibraryPresentationTest` 验证三行标题和单曲菜单不含 `delete`。构建、APK 及真机证据以本次《验证记录》最终结果为准。

### D-023 每个视频独立断点续播

- 背景：用户需要像常见视频播放器一样，对视频 A、B 分别恢复最近观看位置，同时不能让 MP3、队列、锁屏后台播放或自动下一集产生错位。

- 候选方案：A. 页面保存位置，改动小但生命周期不完整；B. 扩展队列恢复器，数据集中但职责混杂；C. 服务层新增独立私有视频进度库。采用 C：`VideoResumeProgressStore` 只存视频的路径哈希或 Media ID、时长、修改时间、位置和更新时间，播放服务是唯一读写者。
- 规则：播放中每 15 秒节流保存；暂停、视频切换、任务移除、服务销毁立即保存；只对手动打开和队列恢复尝试一次恢复，自动下一首和循环不恢复；剩余不超过 30 秒或总时长 10% 视为已看完并清除；时长或修改时间变更、超 180 天时丢弃；最多 500 条。MP3 和 `LastPlayedManager` 不改。
- 验证：新增 `VideoResumeProgressStoreTest` 覆盖同一指纹恢复、文件修改失效、播完清除和音频不建档。运行时真机矩阵仍需覆盖锁屏、全屏、服务异常回收，目标是异常终止最多丢失 15 秒。
- 回滚：移除独立存储调用即可回到原队列恢复，不影响媒体文件、队列数据或 MP3 播放。

### D-028 消除时间驱动的并发测试偶发失败

- 背景：1.6.2 全量测试首次执行时，`PauseableFlowsTest` 期望接收固定序列 `[1, 2, 3, 6, 7, 8, 9]`，实际得到 `[1, 2, 5, 6, 7, 8, 9]`。

### D-029 1.6.3 修复跨入口视频断点续播身份不一致

- 兼容边界：1.6.2 已经只用路径哈希保存、且后续入口又只提供 ID 的历史记录无法从哈希逆推出文件，因此不能安全补配；安装 1.6.3 后首次正常播放并离开视频会自动建立双身份记录，之后所有入口统一恢复。

### D-030 1.7.1 断点续播审计修复

- **上下文**：1.6.3 已消除存储层身份不一致，但审计发现自定义 MediaSession 命令丢弃 `ExpandedMediaItems.startIndex`，队列板也未在替换时间线前解析目标视频续播位置；两处都会造成“记录已存但没有用于实际起播”的风险。
- **风险等级**：中。只影响视频主动打开与队列切换，不涉及手机文件、MP3 数据或网络；错误恢复位置会直接破坏核心体验。
- **候选方案**：一是在 UI 各入口分别传入进度，入口持续增加会再次分叉；二是重写队列模型，成本和回归面过大；三是在既有播放服务中保留展开结果，并让 `QueueBoard` 只请求服务解析起播位置。
- **结论**：采用方案三。`expandAndMapMediaItems()` 保留真实 `startIndex`；自定义命令以该索引选择目标并传入恢复位置；`QueueBoard.commitQueue()` 通过 `resolveQueueStartPosition()` 在替换前保存离开视频并读取目标视频进度。自动下一首和循环的既有“不恢复”规则不变。
- **诊断与验证**：增加“恢复成功、记录未找到、当前项已变更、播放器已推进而跳过”四类脱敏事件。双变体运行 `VideoResumeProgressStoreTest` 及全量测试；真机 A/B 四入口矩阵仍是上线前的唯一运行时证据。
- **回滚**：回退服务内媒体展开和队列起播位置补丁即可回到 1.6.3 的回调恢复逻辑；不会损坏私有进度记录、队列或本地媒体。

- **上下文**：用户在跑步时使用手机扬声器，媒体音量已经最大。现有“增强”依赖系统剩余音量余量，接近 100% 时无法增加响度，不适用。
- **风险等级**：中。音频动态处理会影响声音风格、耗电和 Offload 选择，但默认关闭、可随时关掉；不请求新权限、不新增网络或第二播放器。
- **候选方案**：一是继续提高系统音量，超过硬件上限且容易失真；二是仅使用现有系统效果器，满音量场景收益不稳定；三是复用既有 `ReplayGainAudioProcessor`，让 PCM Float 压缩路径使用固定安全参数。
- **结论**：采用方案三。新增“外放强音”开关，默认关闭。开启后固定叠加 4 dB 增益和 -10 dB 压缩阈值，压缩响亮段为安静段腾出感知响度空间；不宣称突破扬声器物理声压。MP3 与 MP4 音轨共用该链路，锁屏、后台、队列和视频渲染不变。
- **验证与边界**：新增 `ReplayGainAudioProcessorTest` 覆盖开启进入 Float PCM 压缩路径、关闭恢复原 PCM 格式；双变体构建和单测后，红米扬声器的响度、破音、发热、锁屏与视频回归必须人工验收。若体验不佳，关闭开关立即回到原输出；参数调整只改固定常量，不增加均衡器页面。
