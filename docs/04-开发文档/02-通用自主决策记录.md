## 决策原则

以安全、可用、可验证和最小影响面为优先级。结论只建立在源码、构建输出、日志或明确的真机证据上；没有设备证据时标记为待验证，不用推断替代结果。

## 决策记录

### D-001 源码与产品边界

- 背景：用户指定 `FoedusProgramme/Gramophone` 为基础，要求不重构。
- 方案：新建播放器、替换播放器、基于既有 Media3 服务扩展。
- 结论：扩展既有架构；保留技术包名与类名，产品名统一为“本地听歌”。
- 验证与回滚：所有变更集中在扫描、渲染、设置和诊断层；可按单个变更回退。

### D-002 离线方案 B

- 背景：核心本地播放必须不依赖网络，但不做全量依赖重构。
- 结论：不声明 `INTERNET`，移除网络状态权限和可见在线入口；保留底层非可达代码。
- 验证：合并清单与 APK 权限检查；飞行模式真机验证待补。

### D-003 MP4+A​​AC 与完整视频

- 背景：已有 MP4 音频播放，用户升级为需要画面且熄屏继续有声。
- 方案：独立视频项目、仅音频、现有 ExoPlayer 启用视频渲染。
- 结论：启用现有 `GramophoneRenderFactory` 的默认视频渲染器，在完整播放器绑定 `PlayerView`；MP4 扫描维持 AAC 轨筛选。
- 依据：单一 ExoPlayer/MediaSession 可保持队列、锁屏和蓝牙控制一致，不引入第二个播放状态机。
- 回滚：恢复空视频渲染器与封面显示即可回到音频版。

### D-004 行为设置必现崩溃

- 背景：Android 16 日志指向 `BehaviorSettingsFragment.onResume` 的空指针。
- 根因：`settings_behavior.xml` 已删除 `album_covers`，Kotlin 仍以 `findPreference(...)!!` 强引用；API 33+ 必进该分支。
- 方案：恢复节点、判空、删除孤儿逻辑。
- 结论：删除同源的 `onResume` 和点击分支。恢复权限相关 UI 会违背当前产品范围；判空会留下确定的死逻辑。
- 验证：`compileDebugKotlin` 通过；目标机点击路径待回归。

### D-005 崩溃页锁死与诊断体系

- 背景：旧 `BugHandlerActivity` 强制邮件弹窗没有取消按钮，并收集整机 `logcat`。
- 方案：保留旧弹窗、接入远程平台、本地有界诊断。
- 结论：删除旧 Activity 与强制邮件链路；新增私有目录诊断、用户主动导出、清除功能。
- 隐私：不自动外发，不记录媒体路径、标题、URI、剪贴板或输入内容。
- 回滚：删除诊断入口不影响播放器；保留平台默认崩溃处理。

### D-006 发布签名

- 背景：没有用户提供的正式 keystore。
- 结论：交付 SelfBuilt debug 签名 APK，并在文档和产物说明中如实标注；不生成或替代用户的生产私钥。
- 后续：收到正式密钥后单独验证升级路径。

### D-007 构建交付与真实状态

- 背景：用户要求一次性交付可安装 APK，同时禁止把未验证结果当作完成。
- 事实：`assembleDebug` 成功，产物通过 `aapt2` 包名、版本、SDK 与权限检查；`assembleNonMinifiedRelease` 连续失败于上游 Media3 的 ALAC/MIDI Release Java 编译类路径，无法解析 ExoPlayer 音频类。
- 结论：交付 Debug/SelfBuilt APK，并明确其安装边界和 SHA-256；Release 故障单列为 P0 构建债务，不通过伪造密钥、降级证据或把 Debug 改名的方式掩盖。
- 后续：先复现并最小化上游 Release 依赖图，再决定修复 Gradle 依赖、排除无关解码器或升级上游版本的最小方案。

> 2026-08-08 复核：在恢复本机 JDK 21 与 Android SDK 36 后，`:app:assembleNonMinifiedRelease` 通过。此前“Release 依赖阻断”不能再作为当前结论；未闭环项变为正式私钥、签名与升级路径，而不是编译本身。

### D-008 静态检查遗留阻断

- 背景：首次 `lintDebug` 报 9 个错误、127 个警告，无法满足“静态检查完成”的交付标准。
- 方案：仅记录、建立 baseline、修复 9 个错误。
- 结论：修复 3 个不再受支持的 `SessionResult` 错误码、1 个 Media3 实验 API 标记，以及 5 个把百分号当格式符的翻译资源；不建立 baseline 遮蔽现有问题。
- 验证：当前 `lintDebug` 通过，0 个错误、124 个警告。剩余警告列入后续治理，不阻断本次 APK 安装验证。

### D-009 上一首与预设倍速

- 背景：`seekToPrevious()` 的默认 3 秒阈值会在不同进度下重播当前项或切到上一项，锁屏与蓝牙复用了同一语义；速度滑条不符合固定档位的使用诉求。
- 方案：仅改页面按钮、重写媒体会话命令、调整 ExoPlayer 全局阈值。
- 结论：在 ExoPlayer 构建处将上一首阈值设为最大值，确保所有入口统一；速度改为六档单选预设，保留音高滑条与锁定开关，但无历史配置时默认不锁定，重置也不锁定。
- 边界：队列第一项没有上一项，仍回到本项开头；旧自定义速度不再提供可选项，用户需手动选择预设档位。
- 验证：`PlaybackSpeedPresetTest`、相关 MP4/诊断/设置回归测试与 `lintDebug` 通过；1.3.2 Debug APK 构建并完成清单检查。锁屏、蓝牙和第一项边界仍待红米 K80 Pro 真机回归。

### D-010 SelfBuilt 安装包隔离与外部审计复核

- 背景：用户安装 1.3.2 后，Android 16 重复显示 StrictMode 违规弹窗，启动器出现“本地听歌”“Reflections”“Leaks”三个图标，且图标变为圣诞样式。两份外部审计报告同时指出 Debug 构建进入日常交付的边界问题。
- 根因：`GramophoneApplication` 在 `BuildConfig.DEBUG` 下配置 `StrictMode.penaltyDialog()`；`src/debug/AndroidManifest.xml` 覆写 `ic_launcher_xmas` 并注册 `Reflections` 为启动 Activity；`debugImplementation(leakcanary-android)` 注入 LeakCanary 启动入口；debug 源集还合并了 userdebug 代码。
- 方案：保留 `.debug` applicationId 以覆盖已安装的 1.3.2，或切换基础包名并要求用户先卸载。结论：选择前者，避免本次修复再新增一个图标；删除 StrictMode、调试 Manifest、LeakCanary 与 debug/userdebug 源集合并；将用户交付变体设为 `debuggable=false`，保留主图标与唯一 `MainActivity` 启动入口。
- 审计处理：对诊断生命周期、脱敏与存储边界、MP4 大库性能、设置 key 强引用、Release 签名、原生 C++ 覆盖范围逐项记录在《审计复核与后续任务》；静态推断未写成真机结论。
- 验证与回滚：构建后检查 `BuildConfig.DEBUG=false`、合并清单仅一个 `MAIN` + `LAUNCHER`、无 LeakCanary/Reflections/StrictMode 调用；同包名安装覆盖 1.3.2。若发生升级问题，可仅回退本决策涉及的调试源集与构建配置。

### D-011 交付产物验证与风险边界

- 背景：用户需要能覆盖 1.3.2 的可安装包，但目标机本轮未通过 ADB 连接，不能以构建通过替代真机结论。
- 结论：交付 `1.3.3.7e1e6b9`、`versionCode 27` 的 `.debug` 同包名 APK。已完成构建、8 项定向单测、Lint（0 Error/124 Warning）、`aapt2` 权限和唯一启动入口检查、v1/v2 签名与 zipalign 检查。
- 未闭环：红米 K80 Pro 的覆盖更新、图标、StrictMode 弹窗、视频画面、锁屏、蓝牙与飞行模式；既有歌词单测 1 项失败；正式 release keystore 和商店级签名。
- 原则：把未连真机的运行时风险明确交给下一轮验收，不以静态证据掩盖。
