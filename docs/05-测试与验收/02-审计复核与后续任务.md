## 复核原则

两份报告均为 1.3.2 的静态审计，不含本机构建、APK 安装或红米 K80 Pro 真机运行。因此本文件把“源码可直接证明”“静态推断、待真机量化”“不在本次审计范围”分开记录；报告之间冲突时以当前源码和可复现命令为准。

## 本次已修复

| 用户现象 | 源码根因 | 1.3.3 处理 | 验收 |
|---|---|---|---|
| StrictMode 弹窗点“确定”后反复出现 | `GramophoneApplication` 在 Debug 分支调用 `penaltyDialog()` | 删除用户交付路径的 StrictMode/FragmentStrictMode 配置，并把交付变体设为 `debuggable=false` | 启动不再触发 StrictMode 系统弹窗；生成的 `BuildConfig.DEBUG=false` |
| 图标变为圣诞样式 | Debug Manifest 覆写 `android:icon=@mipmap/ic_launcher_xmas` | 删除 Debug Manifest，回退到主清单 `@mipmap/ic_launcher` | 合并清单图标为主图标资源；与 1.1.2 主清单一致 |
| 出现 `Reflections`、`Leaks` 两个额外图标 | Debug Manifest 声明 `Reflections` 启动入口；LeakCanary Debug 依赖注入启动入口 | 删除启动声明、移除 LeakCanary 和 debug/userdebug 源集合并 | 最终 APK 仅 `MainActivity` 同时含 `MAIN` 与 `LAUNCHER` |

## 审计发现判定

| 来源结论 | 复核判定 | 处理与测试任务 |
|---|---|---|
| 诊断导出使用脱离 Fragment 生命周期的 `CoroutineScope` | 源码直接证实，属于低概率但真实的稳定性风险 | P1：改为 `viewLifecycleOwner.lifecycleScope`；测试“点击导出后立即返回/旋转”不崩溃 |
| 诊断路径正则在路径含空格时残留尾部 | 正则缺陷直接证实；但详细报告已追踪当前 `onPlayerError`，未证实该调用点会传入路径/URI | P1 防御性加固：覆盖空格路径、中文路径、`file://`、`content://`；不把当前链路写成已泄露 |
| MP4 扫描对候选项逐个调用 `MediaExtractor`，全媒体观察可能引发重扫 | 源码机制成立；“卡顿、发烫、耗电”的实际程度没有真机数据 | P2：大库 Profiling 后再决定缓存、收窄观察源或防抖；先不以猜测重构扫描架构 |
| 5 处 `findPreference(...)!!` | 当前 XML key 均存在，当前不是故障；历史 `album_covers` 崩溃说明未来裁剪有复发风险 | P2：新增设置页启动冒烟与资源 key 引用检查；按未来功能裁剪时最小化改为安全调用 |
| `LrcUtilsTest` 失败 | 外部报告未运行测试，本次需以实际 JUnit 输出为准；歌词入口已关闭 | P2：复跑单测定位；除非重开歌词入口，否则不扩大到歌词功能重构 |
| `backup_rules.xml`、诊断写入竞态、64 KB 文档偏差、超长事件、导出 ZIP 清理 | 均有代码层面边界或兼容性价值，但不影响 Android 16 当前主路径 | P3：合并为诊断存储加固批次；补单测和旧系统备份规则，不阻断当前安装 |
| `requestLegacyExternalStorage` 和 Manifest TODO | 目标 `targetSdk=36` 下是遗留项 | P3：下次 Manifest 清理合并处理，禁止借机改动媒体权限语义 |
| 正式 Release 变体编译/签名 | 本次已实际执行 `assembleNonMinifiedRelease` 并通过；两份报告基于旧记录的“编译阻断”已过期 | P2：获取私钥后验证正式签名、从已安装包升级、zipalign 与签名校验 |
| 原生 C++/USB/动态加载未审计 | 这是审计范围缺口，不是“已发现漏洞” | P3：如要面向未知媒体或更广泛分发，单独做 JNI、文件解析、USB 描述符和动态加载专项审计 |

## 后续测试任务

1. 红米 K80 Pro：更新安装 1.3.3，确认只剩一个图标、启动无 StrictMode 弹窗；再验证 MP3、MP4 画面、锁屏 60 秒、蓝牙、通知与飞行模式。
2. 设置页冒烟：行为、音频、播放器、实验性、诊断页均能打开；诊断导出后立即返回不崩溃。
3. 大媒体库：准备 MP4/照片较多的媒体库，记录首次扫描、媒体变更后的重扫、CPU 与耗电；没有量化证据前不改变观察源。
4. 诊断隐私：构造含空格/中文路径和 URI 的异常文本，导出包不含路径、标题或 URI；验证包只由用户主动分享。
5. 发布：保留已通过的 Release 变体构建证据；没有私钥和成功签名验证前，继续标为 SelfBuilt，不称正式 Release。

## 不作为已确认缺陷的结论

- 详细报告已撤回“当前播放器错误消息会泄露 `content://` URI”的结论；当前调用点只记录顶层 `error.message`，未读取 cause。保留 URI 脱敏作为未来扩展的防御性工作。
- 两份报告没有执行真机测试，因此“MP4 性能必然恶化”“某设置当前一定崩溃”“正式 Release 的具体依赖根因”等表述不能作为已验证事实。
- 未审查原生 C++ 不能推导出已有原生漏洞；它只定义了安全审计的覆盖边界。
