# 审计复核与后续任务

状态：1.6.3；更新时间：2026-08-15。

外部审计提出的 StrictMode 循环弹窗、三个启动器、圣诞图标、设置页空指针、诊断导出体验和 Debug 签名问题已逐项复核：前五项分别通过移除 `penaltyDialog`、调试启动器/LeakCanary、debug Manifest 覆写、孤儿 Preference 引用和增加一键复制处理。签名问题不能靠代码伪造解决，仍需正式 keystore。新增复核发现：旧单曲、专辑、音乐人菜单能调用系统文件删除；1.5.0 已将媒体项的破坏性入口撤出，替换为应用私有隐藏记录。

1.6.0 新增视频历史进度时，未复用 `LastPlayedManager`：后者仅恢复上次队列，混用会让自动下一集错误跳回旧位置。1.6.3 将独立存储升级为 MediaStore ID 与路径哈希双身份匹配，以消除跨 MediaSession 入口的进度丢失；仍在文件替换、时长变更、播放结束附近、超龄时丢弃记录。尚待红米验证的风险是 HyperOS 异常回收后最后 15 秒的最大丢失边界，以及锁屏/全屏切换下服务回调是否完整。

1.6.1 修正了隐藏歌词测试夹具的空白翻译期望：解析器保留空白原文时间戳，但不会生成对应的翻译行。该变更不改变产品歌词或播放逻辑；1.6.2 双变体全量单测各 56 项均通过。

本轮静态安全复核范围：清单无 `INTERNET`；诊断使用应用私有目录；一键复制事件摘要会脱敏路径和 `content://` URI；FileProvider 仅用于用户主动 ZIP 导出；不扫描或上报用户媒体。待处理风险：第三方依赖 CVE 需结合联网依赖扫描；原生解码器和大 MP4 曲库需要运行时测试；所有真机结论待红米回归。
