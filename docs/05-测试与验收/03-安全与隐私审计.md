## 当前结论与范围

源码主清单不声明 `INTERNET`，移除网络状态权限；诊断仅在用户主动复制或导出时离开应用私有目录。该结论覆盖已查看的源码与清单，不代表依赖无漏洞。1.7.9 双 APK 已完成打包权限、非 debuggable、签名和完整性核验。当前 Redmi 24122RKC7C／API 36 已授权，本地诊断候选已覆盖安装并确认双击；正式1.7.10双包已验包；完整数据保留、最终真机运行矩阵待验。

## 已落实的控制

| 风险 | 控制与边界 |
| --- | --- |
| 网络与统计 | 主清单不声明 `INTERNET`，无自动诊断上传入口；底层历史依赖仍须漏洞扫描。 |
| 本地媒体隐私 | 隐藏／分类保存 MediaStore ID、路径哈希与恢复列表所需标题快照；不复制、移动或删除源文件。 |
| 收藏一致性 | 公共 Favorite 为事实源，不按包名隔离；统一 writer 与进程 Mutex；Android 10 及以下保留 Reader 权威源选择，11 及以上文件锁仅协调遵守协议的写入方。 |
| 视频续播隐私 | 应用私有存储保存视频双身份、时长、修改时间、位置和更新时间，不保存标题或原始路径；不会复制音视频内容。 |
| 外放强音 | 仅保存用户开关；PCM 在内存处理，不保存音频、波形、设备标识或媒体内容。 |
| 诊断泄露 | 路径和 `content://` URI 脱敏，应用私有目录、有界大小、用户显式复制或导出；正式源码去掉逐触点详细诊断，仅保留简短本地 double 事件。 |
| 导出 | FileProvider 仅对用户主动生成的 ZIP 临时授予读取权限。 |
| 启动器 | 用户交付变体保留主 MAIN／LAUNCHER 入口，最终 APK 须核验合并清单。 |
| 当前签名 | nonMinifiedRelease 使用现有 debug keystore，构建类型与签名密钥用途分开判断；必须验证最终 APK 非 debuggable，以及与同包名旧包证书一致。 |

## 未闭环

- 1.7.9 双包验包为已完成历史基线；正式1.7.10双包权限、包名、纯数字版本、非debuggable、ZIP完整性及签名已核验。继续沿用既有 SelfBuilt 签名；旧 1.7.7 双包单签名者与证书一致为兼容比较基线。
- 正式发行密钥管理是未来正式发行事项，不能用切换新密钥破坏已有同包名升级链路；更换签名前须单独设计迁移并验收。
- 协作文件锁不防止非协作第三方修改；写回失败恢复不等同进程强制终止时的事务保证。公共收藏的跨包可见性由 MediaStore 权限与设备策略决定。
- 第三方 CVE 需要可联网的依赖扫描；本地未发现不等于无漏洞。
- 原生解码器、厂商系统策略、应用备份／恢复和双包升级数据保留需要逐项真实设备验证；覆盖成功与双击确认不等于隐藏、分类、收藏、置顶、断点等字段均已对照保留。
