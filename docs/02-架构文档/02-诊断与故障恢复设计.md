# 诊断与故障恢复设计

状态：1.7.10 源码；更新时间：2026-10-10。本地诊断候选原机双击已获用户确认；正式双包及完整运行矩阵待最终验收。

## 设计

- 未捕获异常写入 `filesDir/diagnostics/crash_<timestamp>.txt`；最多 20 条，单条最多 64 KiB。
- 正常事件保存为有界 JSONL；普通事件通过单线程异步写入，播放状态、播放意图、媒体切换和播放器错误均会记录 MIME、状态和原因，但诊断失败不能阻塞播放；崩溃摘要同步落盘。
- 剪贴板摘要取最近 20 条事件，每条最多 1,024 个字符。文本进入存储、剪贴板和 ZIP 前均脱敏本地路径与 `content://` URI；不记录媒体标题、完整 URI、用户输入或剪贴板内容。
- 设置页提供两个明确动作：**一键复制诊断摘要**与**导出完整诊断包**。没有“分享摘要”、自动邮件或自动网络发送。
- 视频续播事件记录“恢复成功”“无匹配记录”“当前项已变更”“播放器已推进而跳过”及恢复秒数，不记录视频标题、文件路径或 URI；用于区分“没有触发恢复”与“恢复到了错误记录”。
- 外放强音开关变化会记录布尔状态，不记录输出设备、媒体标题或路径；用于确认问题是否发生在设置生效前。

- 2026-10-10 临时取证包记录触点、识别与会话状态，证明旧区域 x=800～1600 排除了实际 x=1726～1984。正式源码已去掉详细逐触点诊断，仅保留 `double_tap_play_pause`／`double_tap_unavailable` 等简短本地事件，不记录媒体标题或路径。临时包 1.7.10.gesture-check／43 不作为正式纯数字版本交付。

## 故障恢复

历史事实（1.7.2，2026-08-22）：“行为设置”NPE 的根因是 XML 节点被裁剪后 Kotlin 仍使用 `findPreference(...)!!`。当时已保持声明式权限裁剪并清理孤儿调用，当前继续沿用。后续裁剪 Preference 时必须做 key 全局引用检索，并对每个保留设置页做点击冒烟。

1.7.9 同队列续播修复的代码证据是非空替换区间，验证记录中的旧实现 4 个失败与修复后 6 个通过可用于区分已修复根因和设备待验行为。收藏写入异常应保留诊断与复现步骤，尤其注明 Android 版本、两个应用是否同时操作、公共 Favorite 是否已有第三方修改；进程内 Mutex 和协作文件锁不能证明所有跨应用冲突均已消除。

用户遇到问题时，先复制摘要给开发排查；只有需要完整历史时再导出 ZIP。若诊断页本身异常，不影响播放器和本地文件。
